4. Task 2 — AST Optimizations

What I used AI for:

I used ChatGPT extensively while working on the optimizer.

It helped me understand and implement the three required optimizations: unused variable removal, unused function removal, and function inlining.

We also discussed how to handle scopes, variable shadowing, recursive functions, side effects, and evaluation order.

ChatGPT helped me debug the optimizer and check its behavior using different test programs.

What I took from AI:

I used AI assistance to develop and modify the optimizer implementation in optimizer.py.

This included suggestions for finding unused variables and functions, replacing function calls with inlined code, renaming variables, and preserving expressions with side effects.

I also used AI-generated or AI-assisted terminal commands and test examples to check the optimizer.

What I changed and why:

During testing, I found several cases that needed additional attention.

I worked on preserving variable scopes so that removing an unused variable would not accidentally affect another variable with the same name.

I also checked that recursive functions were not inlined and that variables introduced during inlining received unique names.

Another important problem was evaluation order. For example, an expression containing two scan() calls must read the values in the same order before and after optimization.

The implementation was adjusted so that inlining is skipped when it could change the order of side effects.

I also checked that removing an unused variable does not remove a function call or scan() expression that still needs to execute.

What I understood:

Unused variable removal deletes declarations and assignments whose values are never used, but it must preserve expressions that have side effects.

Unused function removal deletes functions that are not called. This process may need to repeat because removing one function can make another function unused.

Function inlining replaces a function call with the function’s body. Parameters become local variables initialized with the arguments, and variable names must be changed when necessary to avoid conflicts.

I also understood that optimization must not change the program’s behavior. This is why recursion, side effects, variable scopes, and evaluation order are important.
